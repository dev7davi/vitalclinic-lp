# Vital Clinic — Landing Page

Landing page da "Vital Clinic", um SaaS (fictício) de gestão de clínicas médicas. Site estático, sem backend, em português.

    ├── support.js                     runtime do Design Canvas (GERADO — não editar à mão)
    └── assets/

## Arquitetura — por que nem tudo é separável

Este projeto **não é** uma SPA React tradicional com build step (Vite/webpack). É um export do **Claude Design Canvas** (formato `.dc.html`): um "canvas" visual que compila para uma única página React renderizada em runtime, sem etapa de build.

Como isso funciona:

1. `index.html` carrega `support.js`, que busca React/ReactDOM do CDN (unpkg) em tempo de execução.
2. `support.js` faz o parsing do próprio `index.html`: lê tudo dentro de `<x-dc>...</x-dc>` como o **template** da página, e o conteúdo de texto do `<script type="text/x-dc" data-dc-script>` como a **lógica do componente** (classe `Component extends DCLogic`).
3. Esse parsing lê o `textContent` do script **inline** — ou seja, se esse JS fosse movido para um arquivo externo (`<script src="app.js">`), o `textContent` ficaria vazio e **toda a interatividade da página quebraria** (menu mobile, abas da demo, toggle de planos, FAQ, animações, tudo).

**Por isso:**
- ✅ **CSS foi separado** em `assets/css/styles.css`, carregado via `<link rel="stylesheet">` — isso é só CSS normal do navegador, não tem relação com o parsing do runtime, então é 100% seguro.
- ❌ **HTML (template) e JS (lógica do componente) precisam continuar no mesmo arquivo** (`index.html` / `.dc.html`), dentro das tags `<x-dc>` e `<script data-dc-script>` respectivamente. É uma exigência técnica do runtime, não uma escolha de organização.
- `support.js` já é um arquivo separado — é o "framework" (motor de renderização), gerado automaticamente (comentário no topo do arquivo: `// GENERATED from dc-runtime/src/*.ts — do not edit`). Nunca deve ser editado manualmente.
- O React/ReactDOM em si vêm do CDN (unpkg.com) em tempo de execução — não fazem parte deste repositório.

### `index.html` vs `Vital Clinic - Landing.dc.html`

São o **mesmo conteúdo, em dois arquivos**. `index.html` é a versão "publicada" que roda no navegador; `.dc.html` é o formato que o editor visual do Design Canvas espera para reabrir/editar o design. Sempre que um é alterado, o outro é sincronizado (cópia idêntica) — não são arquivos independentes.

## Como rodar localmente

Não tem build step. Basta servir a pasta `export/` com qualquer servidor estático (precisa de HTTP, não abrir como `file://`, por causa do `fetch` que o runtime faz).

**Com auto-refresh no navegador ao salvar (recomendado)** — usa [live-server](https://github.com/tapio/live-server) via `npx`, sem instalar nada permanente no projeto (nenhum `package.json`/`node_modules` fica na pasta):

```bash
cd export
npx live-server --port=8087 --no-browser .
# abre http://localhost:8087/index.html
```

Ao salvar `styles.css` o navegador atualiza o CSS sozinho, sem recarregar a página; ao salvar `index.html` ele recarrega a página automaticamente. (O `python -m http.server` usado antes nesta sessão também funciona, mas exige apertar F5 manualmente a cada mudança — e mostrou instabilidade sob navegação rápida do Playwright, então o Node/live-server é a opção mais confiável.)

## Dentro de `index.html` / `.dc.html`

- `<head>`: carrega `support.js`.
- `<x-dc><helmet>`: preconnect + fonte do Google Fonts (Plus Jakarta Sans + Inter), link para `assets/css/styles.css`.
- `<x-dc>` (corpo): todo o markup das seções — Nav, Hero, Trust bar, Recursos, Como funciona, Demo do produto, Responsivo, Planos, Depoimentos, FAQ, CTA final, Footer.
- `<script type="text/x-dc" data-dc-script>`: classe `Component extends DCLogic` — todo o comportamento interativo:
  - `setMenu` — menu mobile
  - `selectDemo` — abas da seção "Demo do produto"
  - `setBilling` — toggle mensal/anual dos planos
  - `toggleFaq` — acordeão do FAQ
  - `initScrollFx` — navbar dinâmica (encolhe + sombra ao rolar) e scroll-spy do menu
  - `initReveal` — animações de entrada ao rolar (IntersectionObserver)
  - `initCounters` / `animateCounter` — contadores animados (500+, 50mil+, 99%, etc.)

## Histórico de alterações

Este README é atualizado a cada mudança feita no projeto.

- **Animações (JS + CSS)**: scroll-reveal em cards/seções, contadores animados no hero e no dashboard de demo, flutuação contínua nos cards do hero e nos mockups de celular, navbar dinâmica (encolhe + scroll-spy), linha conectora animada na seção "Como funciona", hover mais expressivo nos cards.
- **Paleta**: gradiente `--primary` → `--secondary` (`#009bf8`) aplicado nos botões de CTA principais (Teste Grátis, Comece grátis por 7 dias, Começar agora do plano Profissional) e nos círculos numerados 1-4 da seção "Como funciona".
- **Reestruturação de arquivos**: CSS extraído de `<style>` inline para `assets/css/styles.css`. HTML (template) e JS (lógica do componente) permanecem juntos em `index.html` / `.dc.html` — ver seção "Arquitetura" acima para o motivo técnico.
- **Correção de bug estrutural**: a `<section>` do Hero e seu `<div class="vc-section-pad">` nunca eram fechados no HTML original (exportado do Design Canvas) — isso fazia todo o resto da página ficar aninhado dentro do Hero. Na prática, isso limitava seções que deveriam ser "full-bleed" (Demo do produto, CTA final) a 1240px de largura centralizados em telas largas (>1300px), deixando faixas brancas visíveis nas laterais. Corrigido fechando as tags corretamente.
- **Hero com foto de fundo**: adicionada `assets/img/fundo_hero.png` como plano de fundo da seção Hero (classe `.vc-hero`, com `background-image` em camadas: um degradê branco sobre a foto para manter o texto legível). A colagem de cards do dashboard (`.vc-collage`: "Consultas por Dia", "Distribuição por Status", "Consultas por Horário", "Atividades Recentes", etc.) continua no lado direito, agora flutuando sobre a foto em vez de sobre um fundo liso — texto à esquerda, cards à direita, como no layout original.
- **Menu flutuante ("pill")**: o header virou uma cápsula flutuante fixa (`position:fixed`), com cantos 100% arredondados, margem própria (não encosta nas bordas da tela) e sem ocupar espaço no fluxo do documento — por isso fica sobreposto ao Hero. Visual: transparente com blur (`.vc-navpill`) no topo da página, ficando quase sólido branco (`header.vc-nav-scrolled .vc-navpill`) ao rolar. O menu mobile (dropdown) ganhou o mesmo tratamento, como um cartão flutuante independente abaixo da pill. O botão "Acessar Sistema" passou a ter fundo transparente (antes era branco sólido).
- **Ajustes do Hero (2ª rodada)**: uma primeira tentativa de reduzir a altura do Hero usava `.vc-collage` escalada via `transform:scale(.8)` dentro de um `.vc-dash-wrap` com altura fixa + `overflow:hidden` — isso causava cortes visíveis nos cards do dashboard (bordas cortadas). Essa técnica foi **removida**; a colagem voltou ao tamanho natural (sem `transform`, sem `overflow:hidden`), e a altura do Hero foi aumentada (mais respiro no `.vc-dash-wrap`, `min-height` maior em telas ≥1151px) para dar espaço de sobra a todos os cards, sem cortes. Posição da imagem de fundo ajustada horizontalmente via `background-position`.
- **Trust bar invertida**: a seção "Confiança de centenas de clínicas..." (logo abaixo do Hero) trocou o fundo branco pelo mesmo gradiente azul usado no "Demo do produto" e no CTA final (`linear-gradient(135deg,#013a94,var(--primary) 55%,var(--secondary))`), com texto e ícones em branco/translúcido — consistente com as outras seções de destaque da página.
- **Auditoria UX/UI**: revisão completa (sem alterações de código) cobrindo integridade estrutural do HTML, performance/LCP, animações e `prefers-reduced-motion`, navbar flutuante, consistência de componentes, acessibilidade de tabs/accordion/toggle, responsividade em larguras intermediárias e contraste de cor. Principais achados críticos ainda pendentes: (1) texto do Hero com contraste ~1:1 contra a foto em larguras entre ~1000-1150px, (2) `fundo_hero.png` em PNG de 1,45MB prejudicando o LCP, (3) texto translúcido branco com contraste insuficiente (~2,3:1) nas seções de gradiente azul (Trust bar, Demo do produto, CTA final).
- **Logo com texto preto**: criada `assets/img/logo_vitalclinic_black.png` (remapeamento de cor pixel a pixel do cinza `#b1b1b1` para preto, mantendo o ícone azul e a transparência intactos). Usada no menu flutuante, que agora tem mais contraste sobre o fundo claro/blur; o footer continua usando `logo_vitalclinic.png` original (já é invertido para branco via `filter:brightness(0) invert(1)` sobre fundo escuro).
- **Hero reestruturado — foto em painel dedicado + colagem "ao redor do rosto"** (endereça os achados críticos #1 e #2 da auditoria): o Hero deixou de ter a foto como `background-image` de toda a seção (com degradê apagando o rosto) e passou a ter dois elementos separados dentro de `.vc-hero`: `.vc-hero-photo` (painel absoluto, `right:0`, 46% de largura, sangrando até a borda direita da viewport e até embaixo) e `.vc-hero-text` (texto, `max-width:520px`, sem nenhuma foto atrás). Isso elimina de raiz o bug de contraste ~1:1 entre ~1000-1150px (a foto não fica mais atrás do texto em largura nenhuma). Em telas ≤1150px o painel vira uma faixa horizontal no topo (`position:static`, altura 320px/260px) com o texto embaixo — replicando o padrão visual de referência (foto cheia no topo no mobile/tablet, foto lateral no desktop).
  - Nova imagem `fundo_hero_crop.jpg`: recorte da foto original focando em rosto+tronco (era um banner largo 2172×724 com muito espaço vazio à esquerda; o recorte usa só a metade direita), convertida de PNG para JPEG (`quality=82`) — **949KB → 67KB, ~93% menor**, resolvendo o achado crítico #2 da auditoria (LCP). `fundo_hero.png` e o `fundo_hero_crop.png` intermediário ficaram sem uso (mantidos no repositório, não deletados).
  - A colagem de cards (`.vc-collage`) foi de "coluna ao lado do texto" para "moldura sobre o painel da foto": os 6 cards (`cc-line`, `cc-donut`, `cc-stat`, `cc-heat`, `cc-activity`, `cc-pill`) foram redimensionados/reposicionados (via medição real da posição do rosto no painel renderizado) para deixar uma área livre no centro-superior onde o rosto aparece, com os cards emoldurando ao redor — sem cobrir os olhos/rosto. Esse comportamento é só para desktop (≥1151px); em telas menores a colagem volta a empilhar abaixo do texto (comportamento já existente).

Em telas bem largas (>1700px) isso empurrava o texto pra debaixo/por cima do painel da foto e dos cards. Corrigido com `.vc-hero>.vc-section-pad{width:100%}`, forçando o bloco a ocupar a largura total e respeitar o `margin:0 auto` do `max-width:1240px` normalmente.
- **Logo do menu na cor `--text-2`**: `logo_vitalclinic_black.png` foi reprocessada para usar `#3d4759` (mesma cor de texto secundário do resto do site) em vez de preto puro — mesma técnica de remapeamento de cor pixel a pixel, ícone e transparência preservados.
- **Hover mais suave em todos os botões**: a regra global `button{transition:...}` (e a dos links do menu `nav a[data-nav-link]`) passou de `.18s/.25s ease` para `.4s cubic-bezier(.4,0,.2,1)` — a troca de cor/fundo/sombra no hover fica perceptivelmente mais lenta e suave, em vez de instantânea.

- **Textos do Hero 15% menores no mobile (≤900px)**: título, badge, parágrafo, botões, "Cancele quando quiser" e os números/rótulos das estatísticas escalados para ~85% do tamanho anterior (ex: h1 de 38px → 32px, botões de 16px → 13.5px), para ficar proporcional ao espaço da tela e não competir tanto com a foto atrás.

Foi necessário adicionar o peso `900` ao link do Google Fonts (`Plus+Jakarta+Sans:wght@...;900`) — sem isso o navegador não tem o arquivo da fonte nesse peso e ou ignora (fica igual a 800) ou aplica um negrito sintético de baixa qualidade.

Corrigido trocando os stops brancos do degradê da foto de `#fff` para `rgba(246,249,255,...)` (a cor exata do `--surface`), eliminando o salto de cor. Confirmado por amostragem de pixel: antes ia de `(246,249,255)` para `(255,255,255)` na borda exata; depois fica `(246,249,255)` dos dois lados, sem descontinuidade.

Corrigido comprimindo os mesmos stops (mesmo formato/curva) para terminar em 45% em vez de 88% — agora mais da metade do painel (a parte onde o rosto fica) fica com a foto em cor plena, sem nenhum branco por cima.

Cores em hexadecimal/rgba fixo em vez de `var(--primary)` etc. (na época, as variáveis ainda estavam só no `#vc-top` — ver correção abaixo).
